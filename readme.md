# algorithm-coding · 算法练习室

一个本地启动、直接读写文件的算法练习应用。应用代码与个人题库分开管理。

首次克隆后题库为空，仍可正常启动；把完整题目包放进根目录的 `题库/`，刷新即可练习。`题库/`、`plan/`、运行记录和本地工具不会提交到 GitHub，请自行备份个人资料。

左侧在题目列表与题目详情之间切换，阅读题目、解析和参考代码；右侧主要用于编写 C++，下方输入数据、查看运行结果和历史日志。

## 启动

在当前目录运行：

```bash
./start.sh
```

也可以运行 `python3 app.py`。浏览器会自动打开 http://127.0.0.1:8765 。保持终端运行，按 `Ctrl+C` 停止。

重复执行启动命令时，如果同一端口上已经运行着本仓库的练习室，会直接打开现有应用。若端口被其他程序或另一仓库占用，会提示更换端口。

需要 Python 3.10+ 和 `g++`，适用于当前 Linux / WSL 环境，无需安装 Python 包或前端依赖。页面资源均在仓库内，启动和使用不依赖外网。

```bash
./start.sh --no-browser       # 只启动服务，自己打开浏览器
./start.sh --port 8766        # 端口被占用时换一个
./start.sh --root /path/to/acwing  # 指向仓库根目录，不是题库目录
```

## 日常练习

1. **选题**：首次打开一道题，会把已有的 `main.cpp` 复制到 `attempts/001.cpp`，方便直接运行之前写的代码。没有 `main.cpp` 时使用空白模板。
2. **写代码**：停止输入约 0.6 秒后自动保存，也可以点「保存」或按 `Ctrl+S`。右上角显示保存状态。
3. **运行样例**：输入来源选择「题目样例」，点「运行样例」。自动比较预期输出，忽略空格、换行的差异。
4. **手动运行**：输入来源选择「手动输入」，填入完整的标准输入，点「运行代码」。这是批量标准输入，不是运行过程中交互输入。只报告执行结果，不判断答案正确性。
5. **检查全部**：先运行全部原题样例，再按文件名排序读取本题 `tests/` 中的固定测试。按钮显示实际总数，例如「检查全部（33）」。遇到首个失败就停止，展示实际输出、预期输出和测试来源；结果同时标明样例、手动或完整检查模式。测试缺失或损坏时禁用完整检查并说明原因，仍可运行样例或手动输入。
6. **重新练习**：点「新一轮练习」，创建新的空白 C++ 模板。上一轮会先保存，旧文件一直保留；编辑器上方可切换轮次。
7. **回看运行**：在下方「历史运行日志」选择记录；完整日志也可以直接从目录里打开。

编辑器使用 Ace，支持 C++ 语法高亮、括号匹配、代码折叠、撤销 / 重做、Tab / Shift+Tab 缩进和回车自动缩进。`Esc` 离开编辑区，`Ctrl+S` 保存，`Ctrl+Enter` 运行当前选择的输入。编译错误仍以运行区中的 `g++` 输出为准。

## C++ 智能提示

Ace 接入本地 **clangd** 后支持：

- **即时诊断**：停止输入约 0.7 秒后分析当前草稿，标出未声明变量、语法错误、类型不匹配和常见警告。行号旁有标记，代码下有下划线；点编辑器底部的「C++ 提示」展开问题列表，点具体问题定位，`F8` / `Shift+F8` 跳到下一处 / 上一处。
- **自动补全**：输入名称或 `.`、`->`、`::` 时提供当前作用域的变量、函数和标准库成员。`Ctrl+Space` 手动唤起，方向键选择，Enter / Tab 接受，Esc 关闭；函数补全后可用 Tab 切换参数占位。
- **函数提示**：调用函数时显示签名并突出当前参数，`Ctrl+Shift+Space` 手动查看。鼠标停在符号上可查看类型信息。

提示窗口打开时，Esc 先关闭提示，再次按 Esc 才离开编辑区。保存和运行快捷键保持不变。

当前工作区已安装本地 clangd。其他机器上可以使用系统 `clangd` / `clangd-18` 至 `clangd-22`，或在仓库执行：

```bash
python3 setup-editor.py
```

安装脚本适用于 Linux / WSL x86_64：有 APT 时读取系统软件源的 clangd-18 依赖，将所需包校验后解压到 `.tools/clangd/`，不运行 sudo、不修改系统软件包；无 APT 时使用官方 clangd 20.1.8 发布包。首次下载需要联网，之后离线使用。下载受网络限制时可为该命令设置 `https_proxy`；软件源没有 clangd-18 时请安装系统 clangd。`.tools/` 不需要提交到 Git。

安装或更新应用后，先保存代码，在启动终端按 `Ctrl+C`，重新执行 `./start.sh`，再刷新浏览器。若旧进程还在运行，仅再次执行启动脚本会复用旧服务。

未安装 clangd 时仍有 Ace 的关键字 / 文本补全，底部会明确显示「语义提示未启用」；服务异常时可点击状态重试，保存与运行仍可使用。语言服务日志在 `.workbench/language.log`（自动轮转），可以直接交给助手排查。

诊断分析的是内存中的草稿，不覆盖练习文件、不产生运行记录、不增加通过或失败次数。不同窗口的草稿互相隔离。语言服务复用本机 g++ 标准库路径，检查选项与本地运行保持 C++17 / Wall / Wextra / return-type 一致，但 clangd 和 g++ 的诊断仍可能有差别，最终以编译和运行结果为准。

静态提示不能保证算法正确。例如 `tmp[k]` 与 `tmp[i]` 类型都合法，写错下标不一定能被提示发现，仍需运行样例和完整检查。

## 练习统计

题目列表和当前题目标题旁会显示三个累计值：

- **练习次数**：该题 `attempts/` 中保存的练习轮数。首次从参考代码创建练习也算一轮；修改、保存代码不会额外增加次数。
- **通过次数**：点击「检查全部」并得到「本地通过」的次数。一次检查无论包含多少用例，都只算一次；同一轮可以检查多次。
- **失败次数**：「检查全部」发生答案错误、编译失败、运行错误、超时或输出超限的次数。

题目样例、手动运行、工具异常和未完成的检查不计入通过 / 失败。通过次数加失败次数表示完成的检查次数，不一定等于练习轮数。

统计直接读取练习文件和全部历史日志，旧记录自动计入，不受页面仅展示最近 100 次日志的限制。删除对应练习或日志也会改变累计值。

## 布局与主题

- 点左侧「返回列表」切换题目，点「题目详情」回到阅读；往返时保留当前代码、光标、选区和阅读位置。
- 左侧顶部的左右箭头是「上一题 / 下一题」，按完整题目列表的顺序切换，悬停可看到目标题名。切换前会先保存代码；保存失败时留在当前题目，第一题和最后一题会禁用对应方向。
- 拖动左右面板之间的分隔线调整宽度，双击恢复默认。也可以使用左侧底部明确标注的「面板宽度」滑条和「重置」；分隔线获得焦点后支持方向键、Home / End 和 Enter。
- 上下拖动代码区与运行区之间的分隔线调整运行区高度，双击恢复默认；也支持分隔线上的上下方向键、Home / End / Enter，以及运行区标题栏的上下箭头按钮。高度会记住，窗口变小时会限制高度，为编辑器保留空间。
- 运行区右上角可以「收起 / 展开」，给编写代码留出更多高度。重新展开会恢复调整后的高度，点击运行或查看历史结果时会自动展开。
- 默认使用 One Dark 暗色主题，浅色编辑器使用 GitHub Light Default。左上角太阳 / 月亮按钮切换整个应用和编辑器的明暗，主题与面板宽度会在当前浏览器中记住。
- 窄屏时题目详情和代码区上下排列，避免把编辑器压得太窄。

题目、解析和参考代码只读展示。可在文件中直接编辑，再点题目列表旁的刷新按钮重新载入。若练习代码被外部编辑器修改，保存时会阻止覆盖；先「下载草稿」，再刷新并处理两份改动。

## 文件放在哪里

```text
仓库/
  题库/
    快速排序/
      题目.md                  原题
      解析.md                  思路与复盘
      main.cpp                 参考代码
      practice.json            列表信息与原题样例
      测试说明.md              覆盖、答案验证与生成方式
      generate_tests.py        离线测试制作脚本
      tests/
        001-单个元素.in        测试输入
        001-单个元素.out       对应答案
        generation.json        生成种子、参考代码哈希与验证记录
      attempts/
        001.cpp                第一轮练习
        002.cpp                第二轮练习
      runs/
        <UTC 时间与随机编号>/
          result.json          结果、时间、模式、测试来源、代码哈希
          source.cpp           当时运行的代码快照
          compile.stdout.txt   编译标准输出
          compile.stderr.txt   编译错误和警告
          case-001.in          当时的完整输入
          case-001.expected    当时的预期输出（手动模式没有）
          case-001.out         程序实际输出（已执行的用例）
          case-001.stderr.txt  程序标准错误
  workbench/                   应用代码
  tools/                       离线测试生成、验证工具
  tests/                       应用自身的自动化测试
  AGENT.md                     AI 导入题目的标准流程
  start.sh                     启动入口
```

这些都是普通文件，没有数据库。你可以直接问助手“看一下快速排序最近一次运行为什么错了”，也可以给出页面展示的日志路径。历史运行使用保存的代码、输入和答案快照，因此后续修改代码或测试文件不会改变旧日志。所有计划用例的输入和答案都会留档，尚未执行的用例没有实际输出。

页面预览会截断过长的内容，完整输入、预期输出和程序输出保存在对应日志文件里。程序输出最多保留 4 MB；达到上限会停止并显示「输出过多」。列表显示最近 100 次运行，更早的文件仍保留在磁盘。

整个 `题库/` 被 `.gitignore` 忽略，包含练习代码、题目测试和运行历史；这些文件仍保留在本机，助手可以读取。编译产物在临时目录中，运行后清理。

## 添加题目

交给 AI 导入时，执行 [AGENT.md 中的标准流程](AGENT.md)：自动整理题面，生成易懂的解析、C++17 参考代码、原题样例和自动测试，并完成验证。`AGENTS.md` 是该流程的入口，规则统一维护在 `AGENT.md`。

应用扫描仓库根目录的 `题库/`，每题一个文件夹，含 `题目.md` 即可被发现。完整题目包还应包含解析、参考代码、配置、测试说明、离线生成脚本和已准备好的 `tests/`。保存草稿后点刷新即可发现新增题目，无需重启，也不需要为每种算法修改判题器。

```json
{
  "title": "题目名称",
  "topic": "算法分类",
  "order": 4,
  "samples": [
    {"input": "5\n3 1 2 4 5\n", "output": "1 2 3 4 5\n"}
  ]
}
```

`practice.json` 只存原题样例和列表信息；没有样例仍可手动运行，多个样例可以选择执行。额外测试放入题目的 `tests/`，UTF-8 编码的 `.in` 与 `.out` 必须同名配对。缺少任一对应文件、目录为空或读取失败时，不允许完整检查退化成只运行样例。

测试在**导入时**由 AI 生成：构造合法输入，运行参考程序算答案，再用暴力、独立实现或数学性质交叉核对。应用练习时仅读取文件，不执行参考程序或生成脚本。新题不需要修改公共判题器。

以下是本机题库的示例，题目文件不随 Git 仓库分发；固定种子为 `788`：

| 题目 | 原题样例 | 额外测试 | 检查全部 |
| --- | ---: | ---: | ---: |
| 快速排序 | 1 | 29 | 30 |
| 归并排序 | 1 | 29 | 30 |
| 第 K 个数 | 1 | 83 | 84 |
| 逆序对的数量 | 1 | 32 | 33 |

需要重新制作数据时，在仓库根目录手动执行：

```bash
python3 题库/逆序对的数量/generate_tests.py --seed 788
# 可输出到临时目录，验证其他种子而不更改正式测试
python3 题库/逆序对的数量/generate_tests.py --seed 789 --output /tmp/acwing-inversions-tests
```

脚本先在临时目录生成、编译并验证全部数据，通过后再发布，失败时保留已有测试。生成记录存入 `tests/generation.json`。每次检查会重新读取测试文件，修改后即可使用新内容；刷新可更新按钮中的用例数量。当前使用 Python 标准库，复杂图、树题以后按需采用 CYaRon 等离线工具。

本次从根目录迁入 `题库/` 的改造需要停止旧服务并重新启动一次；如果页面提示服务版本较旧，先保存代码，按 `Ctrl+C` 停止原启动终端，再执行 `./start.sh` 并刷新。后续只添加普通题目无需重启。迁移保留题目 ID、浏览器书签、练习编号和历史统计；旧日志路径在读取时适配新目录，历史文件不批量改写。

同一题目录中的其他 `.md` 和 `.cpp` 文件会出现在「更多资料」中；扩展题如需独立练习，可以整理为另一题的目录并配置相应样例。

## 检查范围

- C++17，编译选项为 `-O2 -Wall -Wextra -Werror=return-type`。遗漏返回值会作为编译错误展示。
- 单个用例运行时间上限 3 秒，地址空间上限 512 MB，输出上限 4 MB。无限循环、异常退出和超量输出会被停止并记录。
- 这是运行自己代码的本地工具，程序具有当前用户的文件权限；资源限制不是不可信代码沙箱。
- 目前支持答案唯一、按空白分隔后精确比较文本的普通题。多解、浮点容差和交互题需要另行扩展判定规则。
- 「本地通过」只代表已执行的用例通过。它不保证所有输入正确，也不验证是否使用了指定算法。官方 AC 仍以 AcWing 提交结果为准。
- 服务仅绑定 `127.0.0.1`，不提供在线提交、账号系统或云同步。

## 应用代码与验证

`workbench/repository.py` 管文件、保存冲突和历史统计，`judge.py` 管运行和日志，`server.py` 提供本机接口。前端在 `workbench/static/`，编辑器、文档展示和运行结果各自独立；`layout.js` 管面板切换与宽度，`results-layout.js` 管运行区高度与展开，`theme.js` 管主题选择。两套配色统一定义在 `styles/base.css`，侧栏、工作区、结果区各有自己的样式文件。布局通过 `--app-shell-sidebar-width` 和 `--results-panel-height` 调整面板尺寸，组件内部样式由各自负责。

Ace 1.45.2 的必要资源、主题和许可证保存在 `workbench/static/vendor/ace/`，无需 CDN、联网加载或 npm 安装。编辑器适配层在 `editor.js`；第三方源码保持原样，局部视觉调整写在 `styles/workspace.css`。

`workbench/language.py` 管理按需启动的 clangd 进程与草稿版本，`static/intelligence.js` 负责诊断、补全和参数提示，相关样式在 `styles/intelligence.css`。关闭应用时会回收语言进程。测试中涉及真实语义能力的用例需要 clangd，未安装时会明确跳过。

```bash
python3 -m unittest discover -s tests -v
```

验证使用原创、独立的合成夹具和临时目录，不依赖个人题库，不会改动你的练习或运行记录。干净克隆也可以运行测试；clangd 未安装时语义集成测试会明确跳过。
